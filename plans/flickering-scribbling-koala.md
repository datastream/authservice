# Plan: Add React Web UI (Tailwind) Integrated as Static Build

## Context
The auth server currently serves a few static HTML pages (login, signup, tokens) directly from the filesystem. The user wants a modern web UI built with React, styled with Tailwind CSS, and served as a static bundle from the existing Go server. The UI should cover three areas:
- **Login & Register**: user authentication flows.
- **OAuth Management**: view/create client tokens, initiate OAuth authorization, view consent.
- **Admin Dashboard**: manage users, view logs, configure OpenFGA models/permissions.
The UI will be built as a separate React project and the production build will be copied into the Go server's static directory so that the Go binary can serve the SPA without a separate dev server.

## Implementation Plan
1. **Create React project**
   - Directory: `frontend/` at repo root.
   - Use Vite (`npm create vite@latest frontend --template react-ts`).
   - Install Tailwind CSS per official guide (postcss, autoprefixer). Configure `tailwind.config.js` to purge `./src/**/*.{js,ts,jsx,tsx}`.
   - Add basic npm scripts: `dev` (vite dev server) and `build` (vite build output to `../static`).
2. **Configure build output**
   - In `vite.config.ts` set `build.outDir` to `../static` (relative to `frontend`). This will place `index.html`, `assets/` etc directly under the repository's `static` folder (create if missing).
3. **Add static serving in Go server**
   - In `cmd/oauthservice/main.go` register a static file handler before other routes:
     ```go
     r.Use(gin.Static("/", "static"))
     ```
   - Ensure the SPA fallback for client‑side routing:
     ```go
     r.NoRoute(func(c *gin.Context) {
         c.File("static/index.html")
     })
     ```
4. **Create React routes & pages**
   - `/login` → `LoginPage` component: form posts to `/login` (existing endpoint) and handles redirect on success.
   - `/signup` → `RegisterPage` component: POST to `/signup`.
   - `/tokens` → `TokensPage` component: GET `/tokens`, POST `/tokens` to create client tokens.
   - `/admin` → `AdminDashboard` component: fetch users (`/manager`), view logs, list FGA models (`/api/v1/fga/models`), and allow CRUD via existing FGA endpoints.
   - Use Axios (or fetch) with `credentials: 'include'` for cookie‑based sessions and attach Authorization header for token‑based calls.
5. **Shared UI utilities**
   - Auth context provider that checks session via `/userinfo` or `/authentication` and stores current user.
   - Error handling wrapper to display API errors.
   - Tailwind‑styled components (buttons, inputs, tables).
6. **Development workflow**
   - Run `npm run dev` in `frontend` for hot‑reload during development (proxy API calls to `localhost:8080` via Vite's proxy config).
   - Run `npm run build` to produce static assets for production.
7. **Testing & verification**
   - Start Go server: `go run ./cmd/oauthservice/main.go -c config.json`.
   - Access `http://localhost:8080/` – the React SPA should load.
   - Verify login, signup, token creation, and admin pages work end‑to‑end.
   - Run existing Go tests (`go test ./...`) to ensure no regression.
   - Lint/format both Go and React code (`go vet ./...`, `npm run lint`).

## Modified / Added Files

## Verification Steps
1. `go run ./cmd/oauthservice/main.go -c config.json` → server starts.
2. In separate terminal: `cd frontend && npm install && npm run dev` → Vite dev server proxies API to Go server.
3. Open browser to `http://localhost:5173/` (dev) and `http://localhost:8080/` (production build) and test all UI flows.
4. Run `go test ./...` – all existing tests must pass.
5. Manual sanity check: logout clears session, protected admin routes return 401 when not logged in.

## Risks & Mitigations
- **Path mismatch**: Ensure the static directory path matches what Gin expects (`static` at repo root). Create the folder if missing.
- **CORS**: Gin already allows origins from config; confirm local dev proxy sets proper origin.
- **SPA fallback**: The `NoRoute` handler must be added after API routes to avoid intercepting API calls.
- **Tailwind purge**: Verify `purge` config includes built files to avoid missing CSS in production.
